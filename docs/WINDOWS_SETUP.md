# Установка Marengo на Windows

ChatGPT Work и Claude Cowork · Личные аккаунты · 24 ноября 2026 г.

Marengo предоставляет доступ к COT и Databento через облачный сервер. Отдельный скилл Marengo Market Data 1.169.3 выбирает источник и строит обычные ценовые графики. Для установки нужны публичный репозиторий, учётная запись Marengo и реквизиты выбранных поставщиков. Приложения получают скилл и настройки через интернет. Оператору достаточно этой инструкции.

## 1. Перед установкой

| Для чего | Что потребуется |
|---|---|
| Приложения | Настольные ChatGPT с режимом **Work** и Claude с режимом **Cowork**, вход в нужный личный аккаунт в каждом |
| COT и Databento | Приглашённая учётная запись Marengo с правами на COT и Databento. Ключ Databento и действующая подписка владельца нужны для котировок. Публичные отчёты CFTC, ICE и LME доступны через COT без отдельного ключа |
| Первое подключение Claude | **Client ID** и **Client Secret** зарегистрированного приложения Marengo **RC5 Claude MCP**. Их передаёт администратор по защищённому каналу |
| MOEX | Для текущих котировок через БКС — свой токен БКС Trade API с правом **«Только для чтения»** |
| Alpha Vantage | Действующее подключение Alpha Vantage или свои реквизиты у поставщика |
| Обновление скилла из GitHub | [Публичный каталог Marengo](https://github.com/dqdp/marengo-marketplace) доступен по HTTPS без аккаунта GitHub, приглашения, SSH-ключа или доступа к приватным репозиториям. Для установки в ChatGPT через каталог нужны Git и Codex CLI |

1. Установите или обновите настольные приложения. Если используете на Windows тот же аккаунт, что на Linux, сначала посмотрите уже подключённые плагины и выполните проверку из раздела 7. Подключение, которое уже работает, можно сохранить. [ChatGPT Desktop](https://chatgpt.com/download/), [Claude Desktop](https://claude.com/download)

2. Откройте [личный кабинет Marengo](https://account.marengo.net/) и войдите под приглашённым пользователем. В разделе ключей проверьте Databento. Если ключ ещё не сохранён, введите его в кабинете. Повторное сохранение ключа может сбросить подтверждение покрытия подписки для этого ключа. При необходимости администратор проверяет доступ к коннекторам и подтверждение плана для текущей версии ключа. Дополнительные источники COT, например EIA, используют собственные реквизиты по мере необходимости.

В **ChatGPT Work** подключите Marengo Data по разделу 2, в **Claude Cowork** — по разделу 3. Затем добавьте скилл из одного и того же публичного репозитория в каждом приложении (разделы 4–5). Для MOEX и Alpha Vantage выполните раздел 6. После установки проверьте данные в обоих клиентах по разделу 7.

## 2. Marengo Data в настольном ChatGPT на Windows

Откройте **Work → Plugins** на компьютере, на котором будете работать. Рабочее подключение к данным предоставляет плагин **Marengo Data** из каталога **Marengo**, версия **0.1.6**. Встроенный скилл и параметры OAuth устанавливаются вместе с ним.

**Если плагин уже установлен.** Посмотрите его источник. Экземпляр `marengo-data@marengo` можно обновить из того же каталога. Путь в логе вида `created-by-me-remote\marengo-data\0.1.4` относится к личной копии Plugin Creator. Для этой копии с ошибкой `unknown field extensions` один раз установите **Marengo Data** из репозитория, как описано ниже. После успешной проверки можно отключить в Desktop прежнюю личную копию. Существующее подключение кабинета Marengo и установку скилла Marengo Market Data можно сохранить.

Для установки или обновления откройте PowerShell под тем же пользователем Windows, что и ChatGPT. Потребуются Git и Codex CLI с командой `plugin marketplace` (раздел 4). Если каталог **Marengo** уже подключён к `dqdp/marengo-marketplace` на ветке `main`, выполните:

```powershell
codex plugin marketplace upgrade marengo
codex plugin add marengo-data@marengo
```

При первом подключении каталога выполните:

```powershell
codex plugin marketplace add https://github.com/dqdp/marengo-marketplace.git --ref main
codex plugin add marengo-data@marengo
```

Проверьте `codex plugin list --marketplace marengo --json`. В списке установленных ожидается `marengo-data@marengo` версии 0.1.6 или новее. Перезапустите ChatGPT Desktop. В настройках MCP выберите **marengo → Authenticate**, войдите на `auth.marengo.net` с выданной учётной записью и подтвердите доступ. В новом чате Work на этом компьютере попросите «Вызови `marengo_platform_catalog` и покажи идентификаторы доступных коннекторов». При наличии обоих разрешений ожидаются `cot` и `databento`.

## 3. Marengo MCP в Claude Cowork

1. В настольном Claude откройте **Customize → Connectors**. Если **Marengo** уже есть, нажмите **Connect**, когда это предложено, и перейдите к проверке. [Страница коннекторов Claude](https://claude.ai/customize/connectors)
2. При первой установке нажмите **+ Add → Add custom connector**. Имя — **Marengo**, **Remote MCP server URL** — `https://mcp.marengo.net/mcp`. Нажмите **Continue**.
3. Выберите **Sign in now → Use your own OAuth client**. Введите **Client ID** и **Client Secret** приложения **RC5 Claude MCP** в поля Claude. Для того же сервера и приложения на другом компьютере подходят те же Client ID и действующий Client Secret. Если администратор заменил секрет, используйте новый. Поле дополнительных заголовков Marengo оставьте пустым.
4. Нажмите **Add**. При установке клиенту на странице Marengo он входит под своей приглашённой учётной записью и подтверждает доступ. При установке для себя войдите в свою учётную запись Marengo. Откройте новый чат **Cowork**, выберите **+ → Connectors → Marengo** и отправьте тот же запрос каталога, что в Work. [Инструкция Anthropic](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

**Для администратора Marengo.** Если реквизиты Claude нужно получить заново, откройте защищённую консоль Logto, выберите **Default tenant → Applications → Third-party applications → RC5 Claude MCP → Settings → Endpoints & Credentials**. Скопируйте **App ID** и действующий **App secret**. В зарегистрированных redirect URI должен быть `https://claude.ai/api/mcp/auth_callback`. В нашей установке консоль доступна через SSH-туннель. Оператор с доступом к серверу может открыть его из PowerShell командой ниже, подставив своего пользователя и адрес сервера. Пока терминал открыт, откройте [консоль Logto](http://localhost:3002) в браузере этого компьютера. После настройки завершите туннель сочетанием Ctrl+C. Клиенту для обычной работы достаточно учётной записи Marengo. [Настройки приложения Logto](https://docs.logto.io/quick-starts/traditional-web)

```powershell
ssh -4 -N -o ExitOnForwardFailure=yes -L 127.0.0.1:3002:127.0.0.1:3002 USER@SERVER
```

## 4. Скилл из репозитория в ChatGPT Work

Для работы с каталогом ChatGPT установите Git for Windows и Codex CLI под тем же пользователем Windows. Если CLI ещё нет, установите Node.js LTS, откройте обычный PowerShell и выполните команды ниже. После установки программ при необходимости откройте новый PowerShell. [Git for Windows](https://git-scm.com/downloads/win), [Node.js LTS](https://nodejs.org/en/download/), [Codex CLI](https://developers.openai.com/codex/cli)

```powershell
git --version
npm.cmd install --global '@openai/codex@0.155.0'
codex --version
codex plugin marketplace --help
```

Версия 0.155.0 проверена на Windows-раннере. Если уже установлен работающий Codex с командами `plugin marketplace` и `plugin add`, сохраните его. При установке через npm, если PowerShell блокирует запуск обёртки `codex.ps1`, в командах ниже используйте `codex.cmd`.

Для построения ценовых графиков скилл запускает скрипт на Python 3 и создаёт SVG. В Cowork проверьте доступ к выполнению кода и созданию файлов. В Work с локальным исполнением сначала проверьте `py -3 --version` или `python --version` в PowerShell. Если обе команды недоступны в той среде, где должен запускаться график, для локального режима установите [Python для Windows](https://www.python.org/downloads/windows/). Для запросов котировок и отчётов через облачный MCP Python на компьютере клиента не требуется.

### Установка из main

**Установка из публичного репозитория.** Откройте обычный PowerShell под тем же пользователем Windows, который запускает ChatGPT. Используйте HTTPS и основную ветку `main`.

```powershell
$repo = 'https://github.com/dqdp/marengo-marketplace.git'
git ls-remote --exit-code $repo refs/heads/main
codex plugin marketplace list --json
```

Если `marengo` ещё не добавлен, выполните следующие команды в том же окне.

```powershell
codex plugin marketplace add $repo --ref main
codex plugin list --marketplace marengo --available --json
codex plugin add marengo-market-data@marengo
codex plugin list --marketplace marengo --json
```

Проверьте запись `marengo-market-data@marengo`: версия 1.169.3 или более новая, `installed: true`, `enabled: true`. Полностью закройте и откройте ChatGPT. В **Work → Plugins → Marengo** откройте **Marengo Market Data** и проверьте его в новом чате. [Каталоги плагинов ChatGPT](https://developers.openai.com/plugins/build/plugins#add-a-marketplace-from-the-cli)

**Если каталог уже есть.** Выполните `codex plugin marketplace list --json` и `codex plugin list --marketplace marengo --json`. Проверьте репозиторий, ветку и установленные плагины.

- Если каталог указывает на этот репозиторий и отслеживает `main`, используйте его для установки или обновления.
- Если отслеживается старая ветка, запишите URL, ветку и версию для отката. Когда единственный установленный плагин — старый `marengo-market-data@marengo`, выполните `codex plugin remove marengo-market-data@marengo` и снова проверьте список установленных плагинов.
- При пустом списке `installed` выполните `codex plugin marketplace remove marengo` и повторите установку из `main` выше. Если есть другие плагины или другой репозиторий, сохраните регистрацию и передайте оператору список и источник.

**Как обновлять.** В том же профиле выполните команды ниже. Откройте карточку Marengo Market Data, примените обновление, если оно предложено, и проверьте установленную версию в новом чате.

```powershell
codex plugin marketplace upgrade marengo
codex plugin list --marketplace marengo --available --json
codex plugin list --marketplace marengo --json
```

## 5. Скилл из репозитория в Claude Cowork

**Подключение публичного репозитория.**

1. Откройте вкладку **Cowork → Customize → Plugins**, затем **Add → Add marketplace → Add from a repository**.
2. Введите **dqdp/marengo-marketplace**, добавьте каталог и откройте его. Выберите **Marengo Market Data → Add**. На дату инструкции редакция с обычными ценовыми графиками имеет версию **1.169.3**. Для каталога используется та же основная ветка, что в ChatGPT.
3. Откройте новый чат Cowork. Через **+** или **/** проверьте доступность скилла **market-data** из плагина **Marengo Market Data**. Если осталась вручную загруженная старая копия, выключите её и повторите проверку в новом чате. [Установка из репозитория в Claude](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)

**Как обновлять.** Оператор публикует следующую версию в `main` того же каталога. Оставьте marketplace подключённым. После публикации откройте его в **Customize → Plugins**, примените обновление, если Claude его предлагает, и сверьте версию установленного плагина. Фиксированный срок автоматического обновления в личном Cowork не подтверждён.

## 6. БКС для MOEX и Alpha Vantage

**БКС.** Для живого bid/ask Московской биржи скилл предпочитает БКС. В личном кабинете БКС откройте **Профиль → Счета и тарифы → нужный счёт → Токены API → Выпустить токен** и выберите **«Только для чтения»**. Скопируйте refresh-токен БКС в настройки каждого клиента.

| Где | Действия |
|---|---|
| ChatGPT Desktop | **Настройки → Интеграции → Плагины → Добавить → Добавить сервер MCP**. Имя **БКС**, тип **Потоковая передача HTTP**, URL `https://be.broker.ru/trade-api-mcp-server/mcp`. В заголовках укажите имя `Authorization` и значение `Bearer ВАШ_ТОКЕН_БКС`, с одним пробелом |
| Claude Desktop / Cowork | **Customize → Connectors → + Add → Add custom connector**, то же имя и URL. Выберите **No sign-in**, в **Request headers** задайте тот же заголовок и оставьте **Required**. Нажмите **Add** и включите БКС в новом чате |

Если ваша версия Claude не показывает **Request headers**, у БКС есть отдельная инструкция для Windows через **Settings → Developer → Edit Config** и локальный `mcp-remote`. Используйте её как альтернативный способ подключения **только БКС**, сохраните остальные записи конфигурации. Токен вводится в настройках, а не в тексте запроса модели. [Официальная инструкция БКС для ChatGPT Desktop и Claude Desktop](https://trade-api.bcs.ru/mcp/)

**Alpha Vantage.** Если прежний официальный коннектор работает, сохраните его и проверьте запросом SPY. На чистой установке в **ChatGPT → Plugins/Apps** найдите **Alpha Vantage**, выберите официальный коннектор и **Connect**. В **Claude → Customize → Connectors** найдите **Alpha Vantage MCP Server** в каталоге и нажмите **Connect**. Завершите OAuth у Alpha Vantage; если поставщик запросит ваш API key, введите его в форме поставщика. Официальный адрес удалённого MCP — `https://mcp.alphavantage.co/mcp`. Доступность real-time US equities определяется тарифом Alpha Vantage. [Подключение у Alpha Vantage](https://mcp.alphavantage.co/), [коннектор в каталоге Claude](https://claude.com/marketplace/connectors/alpha-vantage)

## 7. Приёмка в двух приложениях

Запустите эти проверки **отдельно в новом чате ChatGPT Work и в новом чате Claude Cowork**. Для проверки обновления доступа повторите запрос каталога после истечения исходного токена; у ресурса Marengo его срок на дату инструкции составлял один час.

| Что проверить | Что написать | Признак успеха |
|---|---|---|
| Доступ и COT | «Вызови `marengo_platform_catalog`, затем `marengo_cot_data_catalog` через Marengo» | Оба инструмента выполнились. Пустой кэш нового пользователя сам по себе допустим |
| Databento | «Найди торгуемый фьючерс ES на CME, уточни серию и запроси лучшие bid и ask по её ID. Покажи контракт и время события» | В ответе тот же ID, обе стороны рынка и время события. Полная проверка потока и поиска — ниже. |
| Ценовой график | «Построй обычный ценовой график ES по доступным минутным свечам за 30 минут завершённой сессии. Покажи источник и часовой пояс» | Появился график с инструментом и периодом. Для истории вне подписки при денежном подтверждении можно остановить проверку |
| MOEX | «Покажи текущие лучшие bid и ask SBER через БКС, укажи время» | Указаны БКС и время котировки. Ответ MOEX ISS с задержкой распознаётся как другой источник |
| Alpha Vantage | «Получи SPY через официальный Alpha Vantage и укажи время цены» | Указан Alpha Vantage, получены цена и время в рамках тарифа |

Обязательные проверки Databento для каждого приложения приведены ниже. Если нужный инструмент отсутствует или проверка не завершена, запишите причину и оставьте приёмку этого приложения открытой.

**Проверка автоматического входа.** Запишите приложение, учётную запись и время первого успешного вызова. Полностью закройте приложение. После истечения access token (ориентир — более 60 минут от выдачи) откройте его и повторите вызов в новом чате. Успех — реальные данные каталога без повторного входа. При необходимости администратор сверяет время выдачи и обновления для того же клиента в Logto. Значения токенов в отчёт не включайте.

### Обязательная проверка Databento

Пройдите эти шаги сначала в новом чате ChatGPT Work, затем в новом чате Claude Cowork. Используйте один ликвидный торгуемый контракт GLBX.MDP3. Попросите ассистента выполнить start, оба read и stop одним запросом и записать результаты после остановки. Через 120 секунд без обращений сервер освобождает поток. Сохраните символ, ID, время UTC и результаты отдельно для каждого приложения.

1. **Найдите и выберите серию.** Попросите вызвать marengo_databento_instruments_search для семейства ES.FUT и показать торгуемые серии с датами экспирации. Выберите конкретный raw_symbol и запишите его instrument_id. Если подходящих серий несколько, сначала уточните месяц.
2. **Сверьте параметры.** Через marengo_databento_instruments_list запросите определение выбранной серии. Сверьте символ, ID, экспирацию и шаг цены. Для испытания с опционом сверьте также call/put и страйк. Если серия или параметры не совпали, остановите проверку.
3. **Получите одну котировку.** В marengo_databento_live_get_futures_quote передайте выбранный ID строкой как symbol и укажите stype_in=instrument_id. Сверьте instrumentId в ответе с выбранным ID. Запишите bid, ask и время биржевого события.
4. **Откройте поток и прочитайте обновления.** Вызовите marengo_databento_live_stream_bba с action=start, тем же symbol и stype_in=instrument_id. Сохраните stream_id. Вызовите read с этим stream_id и after=0, затем повторите read с after, равным полученному next_cursor. Сверьте ID контракта, bid, ask и время события. Для успешной проверки получите новое событие с продвинувшимся курсором. При missed_events больше нуля отметьте пропуск и повторите проверку.
5. **Остановите поток.** Даже после пустого чтения или ошибки вызовите stop с тем же stream_id. Для действующего потока ожидается stopped. Если вернулся unavailable, проверьте ID и учётную запись. После двух минут простоя или сбоя, закрывшего поток, этот ID уже недоступен. Запишите фактический статус и повторите цикл с новым ID во время торгов. Для приёмки нужен полный цикл с новым событием и ответом stopped.

Приёмка приложения пройдена, когда поиск и параметры совпали, разовая котировка и обновления потока относятся к выбранному контракту, поток остановлен, а каталог снова открылся после истечения токена без ручного входа. Если для подтверждённого покрытия текущей подписки сервис запрашивает сумму, сохраните сообщение и передайте оператору. Для этой проверки доплату не подтверждайте.

## 8. Переход со старого скилла и локальных MCP

| Старый компонент | Как перейти |
|---|---|
| Самостоятельный **Market Data** из старого ZIP или старого плагина | После установки 1.169.3 выключите прежнюю редакцию при проверочных запросах. Когда новая версия пройдёт проверку в обоих клиентах, старый скилл можно удалить из их списков. Для отката сохраните уже имеющуюся личную резервную копию. Если скилл был распакован в личный каталог `skills`, переместите только его папку из каталога обнаружения в резервную папку |
| Локальные **Databento MCP** и **COT MCP** | Сначала запишите их имена, способ запуска и пути к данным. Отключите старые подключения в каждом клиенте и выполните раздел 7 через облачный Marengo. Установленные программы можно пока оставить для отката. Удаление программ имеет смысл после проверки, что другие проекты и локальные сценарии ими больше не пользуются |
| Новый **Marengo Data** и **Marengo Market Data** | Оба остаются подключёнными в Work. Первый даёт MCP-инструменты и содержит свой короткий встроенный `market-data`; второй выбирает источники и строит графики. Проверяйте название плагина-владельца перед отключением одноимённых скиллов. В Cowork сохраняются коннектор **Marengo** и новый **market-data** |
| **БКС** и **Alpha Vantage** | Оставьте рабочие подключения. Для БКС достаточно одного способа подключения в каждом клиенте |

В Claude локальный сервер мог быть добавлен как **Desktop Extension** или записью в `%APPDATA%\Claude\claude_desktop_config.json`. Для расширения используйте его выключатель. Для ручной записи сначала сделайте приватную резервную копию файла, затем уберите только соответствующий ключ в `mcpServers`, сохранив корректный JSON и остальные серверы. Полностью выйдите из Claude через значок в системном трее и запустите его снова. В ChatGPT/Codex проверьте **Plugins / MCP** и отдельные записи пользовательской конфигурации. Перед изменением ручной конфигурации сохраните её приватную копию. Резервные копии могут содержать ключи.

**Локальные базы COT, кэши, отчёты и оригиналы Databento сохраните.** Облачный профиль Marengo имеет собственный кэш. Локальные данные автоматически в него не переносятся. Если нужен старый локальный материал, сохраните доступ к нему и проверьте чтение до любой деинсталляции. Брокерские токены, подписка Databento и рабочие ключи других проектов сохраняют самостоятельное назначение.

## 9. Диагностика

- **Marengo виден, инструментов нет.** Проверьте **Connect**, включение инструмента в конкретном новом чате, личную учётную запись и права на нужный коннектор. Если каталог открывается, а Databento недоступен, проверьте ключ и доступ к dataset в кабинете Marengo.
- **Снова просит войти через час.** Отметьте приложение и время, проверьте именно этот OAuth-клиент и выдачу `offline_access` у администратора. Обычное продление происходит автоматически при действующем refresh token. Истёкшее или отозванное согласие требует нового входа. Не открывайте старую ссылку авторизации от другой попытки.
- **Скилл есть, но отвечает старый локальный сервер.** Посмотрите поставщика фактически вызванного инструмента, выключите старую запись, начните новый чат и повторите тест с явным названием **Marengo**.
- **На другом компьютере скилл не появился.** Для локального каталога Work установка делается под пользователем Windows на этом ПК. Проверьте `codex plugin list --marketplace marengo --json`, затем перезапустите настольный ChatGPT.

Откройте Work заново и повторите проверку из раздела 7. Проверьте Marengo Data из каталога Marengo по разделу 2. Доступность Cowork на этом компьютере проверяйте в используемом клиенте Claude.

### Данные через Marengo

Этот skill — необязательная помощь в выборе коннектора. Данные доступны через стандартные MCP-инструменты и без skill. Он не устанавливает подключение, не создаёт аккаунт и не задаёт обязательную методику анализа.

### Найти доступную возможность

Используй фактически объявленные инструменты выбранного Marengo-подключения. Если доступны `marengo_platform_catalog` и `marengo_platform_describe`, найди возможность в каталоге и прочитай её описание/schema перед вызовом. Имена аргументов бери из текущей схемы discovery-инструмента.

Capability ID записывается через точки; canonical tool name следует форме `marengo_<connector>_<domain>_<action>`. Конкретные идентификаторы и имена копируй из discovery. Не угадывай tool name по шаблону, названию поставщика или инструкции старой версии. Совместимый alias выполняет ту же операцию — повторный вызов canonical после alias не нужен.

Каталог ограничен правами пользователя. Различай объявленную возможность, наличие credentials, доступность источника и успешный вызов: одно не доказывает другое. Если discovery ещё отсутствует в установленной версии, ориентируйся на доступные MCP tools и их schemas; наличие этого skill не доказывает развёртывание новой версии Gateway.

### Иерархия и выбор источника

| Компонент | Как использовать |
|---|---|
| Marengo Platform | Общая авторизация, личные credentials, discovery и рабочий кэш коннекторов |
| COT connector | Позиционные и связанные данные; Socrata, FMP и LSEG — вложенные upstream-источники COT, а не отдельные коннекторы платформы |
| Databento connector | Futures и options on futures, схемы и операции Live/Historical, которые объявлены конкретным сервером |
| Alpha Vantage MCP | Отдельное подключение со своими tools/credentials; в состав Marengo не входит |

Для COT и связанных Socrata/FMP/LSEG запросов исследуй возможности **COT**, включая состояние нужного upstream. Для futures/options on futures исследуй Databento. Список источников не доказывает готовность их ключей, лицензии и данных. Если пользователь явно выбирает источник, сохраняй этот выбор; недоступность не является разрешением незаметно заменить его.

При запросе Alpha Vantage используй только его отдельно подключённый MCP. Если такого подключения нет, сообщи это; не ищи воображаемую Alpha Vantage capability в Marengo. Equity/ETF options и options on futures различаются — уточняй рынок, только если его нельзя определить из запроса и символа.

### Выполнить запрос

В удалённом режиме получай данные через авторизованный Marengo MCP. Не запускай локальные producer/Python/Node scripts, shell helpers, прямые HTTP/TCP-вызовы поставщика и не читай локальные `.env`, профили или API keys. Это правило сохраняется при отсутствии remote tool, ошибке доступа или timeout. Ключ пользователь сохраняет в личном кабинете сервиса; не запрашивай его в чате или tool arguments.

Выбирай минимальные достаточные dataset, symbols, schema, период и объём из запроса пользователя и актуальной схемы инструмента. Для истории учитывай доступные границы каждого schema; для текущего состояния выбирай фактическую Live-возможность, если она доступна. Описание права или подписки не заменяет успешное получение нужных данных.

Для одной котировки запроси объявленную возможность Live get_futures_quote. Для потока лучших bid/ask и объёмов найди в каталоге Live stream_bba. Используй один stream_id между start, последовательными read по next_cursor и stop. При пропуске сообщи missed_events. Сохраняй отдельно время биржевого события и время получения. Если сервер объявил только однократную котировку, постоянный поток на этом подключении недоступен.

Для поиска по названию, экспирации, типу опциона и страйку используй объявленный instruments.search. Уточни семейство при неоднозначности. При нескольких подходящих сериях покажи варианты. Для уникального совпадения передавай instrument_id строкой в Live. При частичном покрытии обозначай ближайшую серию как ближайшую среди найденных.

Для списка контрактов и их параметров найди instruments.list или объявленный Historical get_range со схемой definition. Семейство выбирай по родительскому символу, конкретную серию — по raw_symbol или instrument_id. Укажи интервал UTC и предел выборки. Учитывай биржу, класс инструмента, изменения определения и полноту ног спредов.

Для historical покрытие Standard привязано к текущему ключу и серверной политике. Внутри подтверждённого покрытия не добавляй собственный автоматический `get_cost`; вне покрытия любая положительная оценка требует разового подтверждения в кабинете. Не объявляй назначенный план проверенным биллингом поставщика. При `confirmation_required` передай сведения об операции/подтверждении и не повторяй вызов автоматически. Технические лимиты, лицензия и права остаются обязательными.

### Представить результат

Сохраняй названия источника/dataset/schema, instrument identity, период, времена и provenance из ответа. Не смешивай futures с options, COT FO с Combined, категории разных отчётов или standard/mini/micro. Не заменяй ICE Brent контрактом NYMEX BZ либо LME prices спотовым бенчмарком без явного запроса. Отсутствие/подавление данных отмечай причиной, а не нулём.

Для продолжения, страниц, оригиналов и экспорта используй доступные операции рабочего кэша и идентификаторы ответа. Не придумывай Research Storage, research revisions или облачные `research_*` возможности. Платформа не исполняет загруженный пользовательский код.

Дальнейший анализ, формулы, отчёт и визуализация определяются запросом пользователя. Не требуй фиксированного промпта, торговли по регламенту, обязательного отчёта/dashboard или сохранения исследования для получения данных. Если задача закончилась получением данных, на этом её можно завершить.
